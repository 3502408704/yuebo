## 同日继续工作四：跨机通信延迟优化（2026-10-03 深夜，已上线）

保留双机分布架构（用户确认不迁移），针对「点击到起播感知变慢」削减 resolve 路径的串行跨区往返。
未命中缓存的解析原先要 **8 次左右**跨区往返（鉴权 SELECT、站点快照、get_resolved、租约写、
账务事务 SELECT FOR UPDATE + 会话 GET + commit、put_resolved），现削减到 **2 次**（get/put_resolved，
跨重启权威保留）：

1. 会话鉴权 + 站点快照 30s 进程内缓存（`ONLINE_MEDIA_AUTH_CACHE_SECONDS=30`，媒体机已开）。
2. 解析租约可关（`ONLINE_MEDIA_RESOLVE_DB_LEASE=0`，媒体机已开）：单 worker 部署进程内
   ResolveCache 已对同 key 单飞，跨区租约只服务多 worker 去重。
3. `authorize_result` 音乐平台在鉴权缓存命中时（`auth_cache_hit` ContextVar）纯内存完成权益判定，
   免开跨区账务事务；网盘平台（有每日额度账务写）与未命中缓存时仍走完整事务。强制下线/账号停用
   的最坏生效延迟 = 30s（解析路径原有 45s 失败短缓存与账务复查语义不变）。
4. 失败冷却（上一轮）：聆澜网络故障按档位冷却 90s，消除失败 hop 的 5s/次白等。

**关于「改公网 TCP 直连」的结论：不采纳。** 上海↔南京物理 RTT（~25-35ms）是延迟下限，SSH 隧道在
链路正常时每查询开销可忽略，换成公网 TCP 不会更快；而把 PostgreSQL/内部端口暴露公网是账号系统的
重大安全退化（数据库不对公网暴露是架构红线）。若将来要彻底消掉跨区 RTT，正道是数据库迁媒体机
（单机化）或腾讯云跨地域 VPC 对等连接（私网但同样受物理 RTT 约束）。

## 同日继续工作三：新档位无法播放根修 + 两机通信优化（2026-10-03 深夜，已上线）

真机实测暴露「新音质挡位无法播放」：nginx 日志见母带解析 200/503 混杂，503 为 21s 预算耗尽。根因两个：

1. **路由层账务闸未接能力目录（主因，即「会员没设计这类挡位」）**：模块成功解析母带后，`authorize_result`
   的 `check_music_quality` 仍走旧四档静态口径 → 母带/24bit/全景声被 422 打回。已修：`authorize_result`
   接收并传递能力目录快照（`main.py` 传 `quality_catalog_snapshot()`），契约回归测试锁定（member+master
   全链 200）。
2. **聆澜失败无冷却烧额度/拖慢解析**（用户提醒点）：已加失败冷却——网络故障/响应无效按档位冷却 90s、
   429 按档位 60s、401/403 全局 60s；网关侧按曲目 45s 失败短缓存原有。音乐解析链路为串行，无并行拉流。

**两机通信优化**（跨区隧道查库延迟）：新增 `ONLINE_MEDIA_AUTH_CACHE_SECONDS`（默认 0=关闭）——
会话鉴权与站点快照的进程内短 TTL 缓存。媒体面网关（`.env` 设 30 已生效）：每请求省去会话 SELECT 与
站点快照两次跨区往返；强制下线/停站最坏生效延迟 = TTL（解析路径 `authorize_result` 仍逐次复查会话，
账务/配额不缓存）。登出即时逐出缓存。`auth_cache_seconds=30.0` 已在生产媒体机确认加载。

模块诊断增强：档位拒绝日志带 `member/quality/actual` 三字段，用于确认会员标记传递是否仍有残余丢失
（曾有 21:15:54 一次「母带解析成功但被判非会员」，待真机复现观察）。
