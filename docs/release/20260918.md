### 服务端

- `pytest server/tests` **969 passed / 2 failed / 21 skipped**
  （2 failed 为 `test_shy_music` 汽水既有失败，与本版无关；21 skipped 含新增
  `test_queue_jobs.py` 4 项——需隔离 PostgreSQL QA 库，本地跳过，逻辑已在生产 E2E 验证）。
- **歌词接口热修（发布前发现）**：9月15日 起 `/v1/lyrics` 全量 503（约 10s 排队超时）。
  根因：一个滞留 `queued` 的孤儿队列作业占住 FIFO 队首，`try_claim_job` 只认领队首，
  后续请求永远认领不到；孤儿源于客户端断开/取消时排队阶段未落终态。
  修复：`_run_resource` 离场即 `cancel_job`（幂等）+ 清理任务自动过期滞留 >10 分钟的
  queued 孤儿（`stale_queued`）+ 手工过期现存孤儿。
  **生产 E2E（修复后）**：网易云歌词 200 / 0.18s / 968 字；QQ 歌词 200 / 4.37s / 1388 字
  （修复前同探针 503 / 10.05s）。部署备份 `app.bak-queuefix-0918/`（main.py + db.py）。
- **版本白名单锁定**：`.env` 改为
  `ONLINE_MEDIA_APP_REQUIRED_VERSION=20260918`、
  `ONLINE_MEDIA_APP_ALLOWED_VERSIONS=20260918`（备份 `.env.bak-release-20260918`），
  重启后实测：`X-App-Version: 20260918` → 放行（无 token 401）；20260917 / 20260915 /
  10002 / 无标识 → 426。`/healthz` 本机 + 公网 200，`NRestarts=0`，无 traceback。
