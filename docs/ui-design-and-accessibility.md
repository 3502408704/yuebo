# 本地音乐播放器 UI、控件与无障碍规范

## 1. 适用范围与优先级

本规范适用于所有 Flutter 页面、对话框、菜单、Snackbar，以及因本项目新增的 Android 原生界面。它是产品交互的实现规范，不替代项目交接文档中的播放、投送和平台通道契约。

规范优先级从高到低为：安全与明确用户操作、可访问性、任务完成效率、视觉一致性、装饰效果。发生冲突时，以 `AGENTS.md` 的项目边界和本规范为准；Flutter 与 Android 官方参考文档用于补充实现细节。

所有用户可见文字、语义名称、错误和状态反馈均使用简体中文。产品中使用“Chromecast”，不使用“Chromium”“浏览器投屏”或“屏幕镜像”指代其媒体投送。

## 2. 产品结构与页面职责

| 区域 | 主要任务 | 不得发生的事 |
| --- | --- | --- |
| 媒体库首页与目录 | 浏览目录、选择歌曲、进入或返回目录 | 仅因获得焦点、进入目录或浏览列表而播放、扫描或投送 |
| 迷你播放器 | 查看当前曲目与目标，打开完整播放器，进行常用播放控制 | 遮挡媒体库的关键内容或替代完整播放器中的详细控制 |
| 正在播放 | 查看元数据、队列模式、进度与所有播放控制 | 直接控制 BASS、平台通道或协议实现；必须经 `PlaybackController` |
| 播放设备对话框 | 查看历史/蓝牙输出，显式搜索网络设备，切换目标或返回本机 | 打开即扫描网络；因 TalkBack 浏览、焦点或普通列表选择而联网/播放 |

页面使用单列、可滚动的任务流。媒体库的焦点顺序为：应用栏导航与操作、目录/歌曲内容、迷你播放器。完整播放器按“曲目信息、目标与模式、进度、传输控制、音量”排列。小屏幕和最大字体缩放时允许内容纵向增加，不能用固定高度、截断或横向溢出隐藏关键操作。

## 3. 视觉与排版

- 使用 Flutter Material 组件和主题 `ColorScheme`、`TextTheme`；不为单一页面另建颜色或字号体系。状态色只能作辅助，必须同时有文字、图标或语义状态。
- 内容采用 4 dp 间距基线，常用间距为 8、12、16、24 dp。列表行以易点按和可换行为先，不为压缩信息减小触控区域。
- 标题、歌曲名和设备名允许换行；曲目次要信息可省略为省略号，但不得省略当前播放目标、错误原因和禁用原因。
- 普通文本及可操作控件文本与背景对比度至少为 4.5:1；大号文本至少为 3:1；图标、焦点和其他非文字状态与相邻表面对比度至少为 3:1。
- 图标是文字操作的补充而非唯一表达。纯装饰图标或图片使用 `ExcludeSemantics` / 空描述；有意义的封面应提供简短内容描述，未知封面不要编造信息。
- 所有可点按控件的有效目标至少为 `48 × 48 dp`，包括 AppBar 图标、迷你播放器控制、关闭按钮和菜单触发器。

## 4. 控件使用规范

| 目的 | 首选控件 | 使用规则 |
| --- | --- | --- |
| 页面返回 | `BackButton` / AppBar leading | 非根目录返回上级目录；根目录交还系统返回行为。返回不播放、不扫描、不投送。 |
| 打开设备选择 | `IconButton` | 使用投送图标，tooltip 为“播放设备”；已有目标时为“播放设备，{设备名}”。 |
| 浏览文件夹或播放歌曲 | `ListTile` | 整行是单一激活目标。文件夹名称先于“文件夹”类别朗读；歌曲副标题显示艺术家、格式和文件大小。 |
| 打开完整播放器 | 可点按的迷你播放器容器 | 给整个容器单一语义名称，内部纯展示文本排除重复语义；不把多个不同操作塞进同一点击区。 |
| 播放、暂停、上一首、下一首、快进/快退 | `IconButton` | 每个图标均有准确 tooltip；无相邻曲目时禁用并可感知，不能保留空回调。 |
| 进度与音量 | `Slider` | 进度为可定位控件，语义含当前位置和总时长；音量语义含百分比。远端不支持音量时禁用并说明“此播放目标不支持音量控制”。 |
| 少量互斥选项 | `PopupMenuButton` | 用于播放速度、播放模式等短选项；tooltip 说明当前值，菜单项使用可理解的中文标签。 |
| 搜索网络设备 | 有文字的 `TextButton.icon` | 固定文案“搜索新设备”。仅此明确操作调用远程协议扫描；进行中显示加载并禁用重复触发。 |
| 设备、蓝牙输出和返回本机 | `ListTile` | 名称、协议和选中状态同时可见/可读。网络设备语义为“播放设备，{协议}，{设备名}”；蓝牙仍是本机音频路由，不称为网络投送。 |
| 关闭模态界面 | 带 tooltip 的 `IconButton` 或明确文字按钮 | 文案为“关闭”。连接进行中可暂时禁用，但操作结束后必须恢复关闭路径。 |
| 破坏性或不可逆操作 | 明确文字按钮 + 确认对话框 | 当前播放与投送切换不是破坏性操作，不额外增加确认；但必须明确告知其结果。 |

不要用手势作为唯一通道。长按、拖动和滑动必须有等价的按钮、Slider 或键盘/D-pad 操作。不要把列表的 `onFocusChange`、`onSelected` 或屏幕阅读器探索回调用作网络、播放或写入的触发器。

## 5. 页面与状态细则

### 媒体库

- AppBar 标题为“本地音乐”。非根目录提供标准返回箭头；右侧始终提供播放设备入口。
- 文件夹行清晰显示文件夹属性；进入文件夹仅改变浏览路径。歌曲行的激活表示明确点播：本机目标调用本机播放，远程活动目标按当前协议投送。
- 加载媒体库时提供可见加载状态；无歌曲、无权限和扫描失败分别给出原因及下一步，例如“未授予音乐读取权限，请允许后重试”。不要只显示空白列表。
- 当前曲目存在时显示迷你播放器，至少包含曲名、艺术家、播放目标和播放/暂停状态。它打开“正在播放”页面，页面转场后焦点从页面标题开始，不自动跳到进度条。

### 正在播放

- AppBar 标题为“正在播放”。曲目信息按“歌曲名、艺术家、专辑、格式/码率/文件大小”呈现，同一组只朗读一次。
- 播放目标和播放模式使用文字值，不能只使用勾选或模式图标。远程目标不支持的控制保持可见、禁用，并显示原因。
- 播放进度更新只刷新视觉值和 Slider 语义值，不移动焦点、抢占读屏或每秒播报。用户显式定位完成后才播报一次结果。
- 播放、暂停、切歌、定位和音量的失败保留当前目标与页面，显示可恢复错误；除非用户明确选择“返回本机播放”，不得自动回退到手机扬声器。

### 播放设备对话框

- 标题固定为“播放设备”。打开时只读取历史目标和 Android 当前音频输出；网络发现必须等待点击“搜索新设备”。
- 列表按“本机、蓝牙、各网络协议”分组；组标题标记为 heading。设备以 `protocol:id` 去重，历史网络设备以“上次连接”标识，真正开始时仍由协议重新确认可用性。
- 点按可用网络设备是明确的连接/开始播放操作；连接期间禁用重复选择和搜索，并用“正在连接 {设备名}”描述进度。蓝牙选择只切换系统音频路由，不启动 HTTP 服务。
- 当前设备必须同时以文字/语义“当前播放设备”和勾选图标表示。切换成功后播报“已连接 {设备名}”“已切换到 {设备名}”或“已返回本机播放”。
- 初始加载、搜索、连接和失败状态均应能被读屏感知。错误应说“操作失败，请重试。”，并保留可执行的重试或关闭路径；不泄露原始异常给普通用户。
- 对话框是模态的，可通过“关闭”、系统返回或可用的返回手势退出。关闭后把焦点恢复至打开它的“播放设备”按钮；刷新、状态更新与成功播报不得强制移动焦点。

## 6. Flutter 语义、焦点与反馈

- 优先使用原生 Material 组件产生语义。只在需要合并文字、补充状态或提供 Slider 增减动作时使用 `Semantics`；使用 `excludeSemantics: true` 后，必须在父语义中完整补回名称、角色、状态和动作。
- 每个可操作控件有简短中文名称。图标按钮必须同时设置 `tooltip`；不要把“按钮”“图标”等控件类型重复写进普通名称，除非名称本身不能表达动作。
- 使用 `Semantics(header: true)` 标记页面和列表组标题；用 `selected` 表示当前设备/模式，用 `enabled` 与可见说明传达禁用和原因，用 `liveRegion: true` 承载错误、加载完成等变化。
- 重大且短暂的成功结果通过 `SemanticsService.sendAnnouncement` 播报一次；不要为常规轮询、进度、焦点移动或重复状态反复播报。建议固定文案如下：

| 事件 | 播报文本 |
| --- | --- |
| 网络搜索开始 | 正在搜索新设备 |
| 网络搜索完成 | 已找到 {数量} 个新设备 |
| 正在连接 | 正在连接 {设备名} |
| 网络投送成功 | 已连接 {设备名} |
| 蓝牙输出切换成功 | 已切换到 {设备名} |
| 返回本机成功 | 已返回本机播放 |
| 操作失败 | 操作失败，请重试。 |

- 保持键盘和 D-pad 焦点顺序与视觉任务顺序一致。Enter/Space 激活按钮和列表行；Slider 可用方向键/辅助技术的增加、减少动作调整。异步刷新不得偷走焦点；移除当前聚焦项时，将焦点放到同组最近的可用项或该组标题后的第一个可用控件。
- 任何连接、扫描、播放、seek、音量写入或返回本机操作均须来自用户明确激活的控件。焦点、悬停、选中外观、TalkBack 浏览、页面构建和轮询均不能触发这些动作。

## 7. Android 原生界面与系统交互

- 项目以 Flutter 为主。新增原生 Android View、XML 或 Compose 界面前，先阅读 `docs/references/android-native-ui-design.md`；使用平台原生控件、中文 content description / 可访问名称，以及至少 48 dp 的点击目标。
- 原生桥接的权限、MediaRouter、Cast 会话或系统选择器仅返回状态给 Flutter；不能因 Flutter 焦点变化而启动发现、连接或播放。
- 系统通知、锁屏、耳机和 Android 媒体会话中的命令必须与页面控制共享 `PlaybackController`。标题为曲目，远程投送时描述包含设备名；命令失败要通过应用内可恢复错误反馈，且不自动回退本机。

## 8. 验收清单

每次修改用户界面、控件行为或用户可见状态后，至少人工验证受影响流程：

- 在最大字体缩放和小屏幕下，标题、设备名、错误、当前目标和关键控制均完整可见且仍可点按。
- 使用 TalkBack 从头浏览媒体库、迷你播放器、完整播放器和播放设备对话框；名称顺序自然，不重复朗读，状态、禁用原因、加载、错误和成功均可感知。
- 不使用触摸完成同一流程：键盘/D-pad 可进入目录、点播、打开/关闭对话框、搜索、选择设备、播放/暂停及操作 Slider。
- 焦点浏览、TalkBack 浏览、打开设备对话框和普通列表选择均不会扫描、连接、投送或播放；点击“搜索新设备”或设备后才发生相应操作。
- 在灰阶、色觉缺陷与高对比度环境下，选中、连接中、错误和禁用状态仍可区分。
- 对本机、蓝牙、DLNA 和 Chromecast 分别验证支持与不支持的控制、失败恢复和“返回本机播放”；Chromecast 与 DLNA 仍须完成交接文档规定的真机验收，才可宣称设备支持。
