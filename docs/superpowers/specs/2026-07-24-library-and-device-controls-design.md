# 文件夹媒体库与设备控制设计

## 目标

将本地音乐库从扁平歌曲列表改为按真实目录层级浏览；提供完整播放器；连接 DLNA 设备后，将其作为默认播放目标。

## 交互

- 媒体库的每一层显示子文件夹及当前目录的歌曲。进入、返回目录只改变浏览位置，不会播放或投送媒体。
- 当前歌曲出现底部迷你播放器，显示曲名、艺术家、播放目标以及播放/暂停。点击迷你播放器打开完整播放器。
- 完整播放器提供上一首、下一首、播放/暂停、快退、快进、进度条、当前/总时长与音量控制。
- 用户选择并成功连接设备后，设备名称成为当前播放目标。之后从任意目录选择歌曲都会直接投送到该设备。
- 设备不支持的控制仍显示，但禁用并标明“不支持”。连接或控制失败显示可恢复错误，不自动回退到手机扬声器。

## 数据与状态

- 媒体扫描结果包含每首歌的真实相对目录；界面从这些路径即时构建目录层级，不新增持久化数据库或依赖。
- 播放状态保存点歌时所在目录形成的固定队列、当前索引、播放位置、播放目标、音量和设备能力；之后浏览其他目录不改变这支正在播放的队列。
- 上一首/下一首按这支固定队列的歌曲顺序切换；设备端切歌由应用加载相邻曲目实现。
- 已连接的 DLNA 会话会在切歌时复用，直到用户主动断开或会话出现错误。
- DLNA 播放/暂停/定位/音量命令仅在设备声明支持时启用；缺少音量能力时禁用音量控件。

## 无障碍与错误处理

- 每个可操作控件具备简短、明确的中文名称；播放状态、当前目标、禁用原因和操作失败能被辅助技术感知。
- 所有控制均可通过键盘或 D-pad 操作，焦点顺序遵循媒体库、迷你播放器、完整播放器的任务流。
- 进入目录、选择设备和获得焦点均不触发播放或网络操作；播放、投送、定位与音量变化必须由明确操作触发。
- 设备失联或命令失败保留当前目标和可恢复错误状态，提供重试或返回本机播放的明确操作。

## 验收

本次按用户要求不新增或运行自动化测试。人工验收应覆盖：

1. 目录进入与返回、目录内点歌及相邻曲目切换。
2. 迷你播放器和完整播放器的所有本机控制。
3. 连接设备后从不同目录选歌默认投送、设备端播放/暂停/定位/音量，以及不支持控制的禁用提示。
4. 设备断开、投送失败、返回本机播放的恢复路径。
5. TalkBack、键盘/D-pad、大字体下的名称、焦点和状态反馈。
