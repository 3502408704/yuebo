# 媒体库专辑操作与元数据设计

**日期：** 2026-08-04

## 目标

保留媒体库根据音乐标签自动发现专辑的能力，同时让用户通过“导入文件夹”建立的专辑获得封面、简介和可编辑的应用内信息。所有专辑使用一致的详情、长按操作和 TalkBack 自定义操作；所有曲目在一个统一入口中查看并编辑元数据。

## 范围

- 保留自动发现的专辑，并与已导入专辑在同名时合并显示。
- 为专辑条目加入长按菜单、等价的无障碍自定义操作和“从专辑列表移除”确认。
- 让直接导入文件和文件夹导入读取音频自身的标题、艺术家、专辑和时长元数据。
- 合并“查看文件详情”和“编辑元数据”；曲目编辑只能从长按菜单或等价 TalkBack 操作进入。
- 保持“导入文件夹”每次选择一个目录的现有流程。

不修改源媒体文件、播放列表、播放器、投送、蓝牙或系统文件选择器行为，也不新增依赖。

## 专辑聚合与移除

新增仅供 UI 使用的统一专辑条目，由两类来源构成：

- 自动专辑：从当前媒体库曲目的非空 `album` 元数据分组得到。
- 导入专辑：由已持久化的 `ImportedAlbum` 得到。

使用规范化后的专辑名称作为合并键。同名条目合并为一个卡片，曲目按 `metadataKey()` 去重；导入专辑的封面、封底、简介、艺术家及专辑编辑信息优先。纯自动专辑仍可查看轨道详情并编辑每条轨道元数据，但没有目录专辑专属的封面、简介编辑数据。

“从专辑列表移除”不会删除文件、目录访问权限或播放列表。应用持久化被隐藏的合并键，自动刷新后也不会重新展示该专辑。已导入专辑同时删除其应用内登记。该确认对话框明确说明源文件与播放列表会保留。

## 元数据解析

`buildExternalTrack` 在读取外部文档时，使用 `MediaMetadataRetriever` 一次取得时长、标题、艺术家和专辑：

- 有效的嵌入标签优先；标题无标签时回退为不含扩展名的显示文件名，艺术家回退为“未知艺术家”，专辑回退为空。
- CUE 解析后的 `TITLE`、`PERFORMER` 和专辑 `TITLE` 继续优先于音频文件标签；缺少 CUE 字段时才采用音频元数据。
- 用户保存的应用内元数据覆盖仍在所有来源恢复后最后应用。

因此直接导入、文件夹导入、CUE 分轨、自动专辑分组和已导入专辑详情共用同一套元数据优先级。

## 交互与无障碍

专辑卡：

- 点击只打开详情页，不播放。
- 长按打开菜单。已导入专辑提供“查看专辑详情”“编辑专辑”“从专辑列表移除”；自动专辑提供“查看专辑详情”“从专辑列表移除”。
- 同一张卡通过 `CustomAccessibilityAction` 提供等价中文操作，不依赖 TalkBack 长按手势。

曲目卡和专辑详情轨道行：

- 点击播放。
- 长按打开菜单，提供唯一的“查看并编辑元数据”操作及“删除”。媒体库曲目保留既有复制、剪切、分享和收藏等适用操作；专辑详情轨道至少提供查看/编辑和删除。
- 用同样的自定义无障碍操作暴露菜单命令；专辑轨道不再有单独的“编辑元数据”按钮或焦点。
- 菜单、对话框关闭后恢复到启动操作的卡片或行，异步保存使用中文 polite live region 通知。

曲目删除继续采用现有的确认和 Android 系统授权路径，删除目标是该曲目的源媒体；CUE 分轨继续拒绝单独删除并给出中文原因。它与“从专辑列表移除”不同，后者永远不删除源文件。

统一的“查看并编辑元数据”对话框显示文件格式、时长、路径和大小等只读信息，并把标题、艺术家和专辑显示为可直接编辑的字段。保存只更新应用内覆盖，不写入媒体文件。

所有可点击卡片、菜单项、对话框按钮和可编辑字段维持至少 48dp 目标尺寸；图像仍不产生额外的 TalkBack 焦点。

## 测试与验证

自动化测试覆盖：

- 自动专辑和导入专辑按同名合并，曲目去重且导入信息优先；隐藏专辑不会在刷新后恢复。
- 外部曲目的标签回退逻辑；CUE 字段与用户覆盖的优先级。
- 移除导入专辑只更新应用内状态，不调用删除源文件或播放列表的路径。
