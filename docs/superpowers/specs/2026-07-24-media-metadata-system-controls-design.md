# 媒体信息与系统控制设计

## 目标

在媒体库显示每首歌曲的格式和文件大小；将播放器注册为 Android 系统媒体组件；使系统返回手势按目录层级导航；修正文件夹的无障碍朗读顺序。

## 媒体库信息与导航

- MediaStore 查询增加媒体字节大小，`Track` 保存 `sizeBytes`。
- 歌曲副标题显示艺术家、格式和易读文件大小，例如“歌手 · MP3 · 8.4 MB”。格式从 MIME 类型推导，未知格式显示原 MIME 类型。
- 文件夹的辅助技术名称为“<文件夹名称>，文件夹”，名称在类别之前朗读。
- 根目录以外使用 `PopScope` 拦截 Android 返回手势、返回键及系统导航：仅返回上级目录，不播放媒体或启动网络操作；根目录才交还正常退出行为。

## 系统媒体控制

- 应用级播放控制器是队列、当前曲目、进度、音量和播放目标的唯一状态来源；页面只负责显示并发送明确命令。
- 使用现有 `audio_service` 初始化 Android 媒体会话，发布当前 `MediaItem`、播放状态、队列位置与可用控制。
- 通知栏、锁屏和耳机的播放/暂停、上一首、下一首和定位命令通过同一控制器分派：本机时调用 BASS，投送时调用活动 DLNA 会话。
- 投送期间系统媒体标题仍是歌曲，副标题/描述包含设备名称；任何命令失败显示可恢复错误，绝不自动切换为本机播放。
- 音量不作为系统媒体会话的必需命令；应用内控件继续依设备 RenderingControl 能力启用或禁用。

## 无障碍与验收

- 所有新增状态文本和命令具有简短中文语义；动态进度与媒体会话更新不移动 Flutter 焦点，也不每秒强制播报。
- 人工验收覆盖：格式/大小显示、文件夹朗读、返回手势层级导航、通知栏/锁屏/耳机在本机与投送两种目标下的控制、投送失败恢复以及大字体和 TalkBack。
- 按用户要求不新增、不修改或运行自动化测试。
