# 歌词无障碍、桌面小组件与睡眠定时设计

**日期：** 2026-08-17  
**状态：** 已获用户确认，待编写实施计划

## 目标

完善歌词朗读和歌词来源，确保桌面小组件在 TalkBack 下能读出歌曲名、歌手和当前歌词，并重写睡眠定时器，使其同时支持按时间和按曲目停止，且状态清晰可感知。

## 约束

- 继续使用现有 Jetpack Compose、`NativeMusicViewModel`、BASS、MediaSession 和 `RemoteViews` 架构。
- 不新增第三方依赖，不改变 QQ 音频播放的同平台回退规则。
- 所有 UI 文本、状态和错误使用简体中文。
- 所有可操作控件至少 48dp；每个无障碍操作只暴露一个语义节点。
- TalkBack 浏览、焦点移动和组件刷新不能触发扫描、连接或其他非必要网络操作。
- 修改使用局部 `apply_patch`；不回退工作树中与本需求无关的用户改动。

## 设计

### 1. 歌词朗读与偏移调节

`lyricTtsOffsetMs` 继续作为持久化和播放逻辑的内部单位。界面不再把偏移量表现为进度条，而是显示带符号的秒数和步进操作：

- `-1 秒`：朗读延后 1 秒；
- `0 秒`：不调整；
- `+1 秒`：朗读提前 1 秒；
- 继续沿用当前的 `-2000..+2000ms` 边界，避免无依据地扩大设置范围。

视觉控件由减按钮、当前值和加按钮组成。当前值节点同时提供 Android 可调节语义，使 TalkBack 用户可以用上下滑动手势逐级改变数值。每次改变都更新可见状态文本和无障碍状态描述，例如“歌词朗读偏移，提前 1 秒”。

朗读设置分为三个独立节点：

1. “跟随播放进度朗读歌词”开关；
2. “语音引擎，当前……”选择器；
3. “歌词朗读偏移，……”可调节控件。

开关行保留 Material `Switch` 的视觉表现，但子 `Switch` 不再单独进入无障碍遍历；父行承担切换操作。引擎选择保留应用内选择能力，异步枚举完成后再选择持久化引擎；持久化引擎不可用时选择第一个可用引擎并显示失败/回退状态。歌词切换、暂停、退出和引擎更换时停止上一句朗读，避免残留语音。

### 2. QQ 歌词获取

QQ 播放和歌词解析分离处理。歌词获取顺序为：

1. 使用当前 QQ `platformId` 调用 ShyMusic QQ 歌词接口；
2. 若无结果，使用现有妖狐 QQ 搜索结果的 `lrctxt`；
3. 若 QQ 仍无歌词，按归一化后的歌名和歌手在其他已支持平台中只搜索歌词，严格确认歌曲匹配后返回歌词；
4. 所有来源都为空时返回空，并显示“这首歌没有可读取的歌词”，不显示成功状态。

跨平台只用于歌词，不改变 QQ 音频地址、音质和播放平台。歌词结果必须经过标题归一化和歌手匹配，不能因为同名歌曲直接套用错误歌词。对 QQ 接口的空响应、异常响应和非歌词文本统一按无结果处理。

### 3. 桌面小组件

组件继续保留上一首、播放/暂停、下一首三个操作。布局改为 `FrameLayout` 分层结构：

- 顶部歌曲名；
- 歌手行；
- 当前歌词行；
- 底部控制区。

背景使用静态深色半透明玻璃形状、圆角和细边框；歌词使用暖橙强调色，正文保持足够对比度。RemoteViews 不引入实时模糊或复杂动画。

组件广播从“合并标题”改为分别传递歌曲名、歌手、歌词和播放状态。信息区只暴露一个可访问摘要节点，播报格式为“歌曲名，歌手，当前歌词”；可视的歌手和歌词文本隐藏重复无障碍语义。没有歌词时使用“暂无歌词”。三个控制按钮各自使用简短中文语义名，播放按钮根据状态播报“播放”或“暂停”。

歌曲切换、播放状态变化和当前歌词变化都通过同一渲染函数刷新所有组件实例。歌词更新继续节流，并且只有歌词内容或播放状态发生变化时才刷新。

### 4. 睡眠定时

同一时间只允许一个睡眠定时任务。新的定时设置会取消并替换旧任务。支持两类模式：

#### 按时间停止

保留现有预设：5、10、15、30、45、60、90 分钟。使用 `SystemClock.elapsedRealtime()` 计算截止时间，周期性更新剩余毫秒数；到期后暂停播放、清理任务并显示“睡眠定时已暂停播放”。

#### 按曲目停止

增加以下选项：

- 播完本曲；
- 播完 3 曲；
- 播完 5 曲；
- 播完 10 曲。

当前正在播放的曲目计入数量，因此“播完 10 曲”表示当前曲结束后再完成 9 曲。只有自然播放完成并进入自动切歌路径时递减计数；用户手动切歌不递减，避免误触导致提前停止。最后一曲结束时直接暂停，不短暂开始下一首。当前没有歌曲时，曲目选项禁用并显示原因。

定时面板显示一个小型环形倒计时动画：

- 时间模式中心显示“分 秒”；
- 曲目模式中心显示“还剩 N 曲”；
- 环形进度表示剩余比例；
- 动画停止、取消或完成时清理；
- 文本状态和语义描述始终是倒计时工作的主要表达，动画不是唯一状态来源。

面板提供明确的“取消定时”操作，并通过可见状态文本和 polite live region 感知开始、替换、取消和完成。

## 数据流与错误处理

- `NativeMusicViewModel` 仍是歌词、播放进度、组件广播和睡眠定时的唯一协调点。
- 播放完成回调先处理曲目定时，再决定是否自动切歌。
- TTS 初始化、QQ 网络请求和组件广播均使用现有 `runCatching`/状态反馈模式，异常不得导致播放线程或 Activity 崩溃。
- QQ 歌词失败只影响歌词状态，不影响已经成功建立的音频播放。
- 组件没有实例时直接跳过刷新；组件 PendingIntent 继续使用不可变标志。

## 验收标准

1. 歌词朗读偏移以秒显示，按钮每次改变 1 秒，TalkBack 上下滑动可逐级调节，并能实时读出当前值。
2. 朗读开关、引擎选择和偏移控件不会产生重复无障碍节点；引擎变更后下一句使用新引擎。
3. QQ 在线歌曲能按既定顺序获取歌词；主接口无歌词时能走兜底；错误匹配不会显示错误歌词。
4. 桌面组件在 TalkBack 下能按一次信息节点读出歌曲名、歌手和当前歌词，按钮顺序和操作正常。
5. 桌面组件视觉层级清晰，歌曲名、歌手、歌词和控制按钮在小尺寸和大字体下不重叠。
6. 时间定时到期暂停播放；曲目定时按当前曲计数；“本曲”和“10 曲”均在正确边界停止。
7. 倒计时动画运行、取消和完成状态正确，且不替代文字/语义反馈。
8. 相关单元测试、`compileDebugKotlin`、`testDebugUnitTest`、`assembleRelease` 和 `rtk git diff --check` 均通过。
9. 设备上完成启动、播放、歌词朗读、QQ 歌词、桌面组件 TalkBack、时间定时和曲目定时冒烟检查；`logcat` 无本应用 FATAL/ANR。

## 测试范围

- 偏移秒数与毫秒值互转、正负方向和边界值；
- QQ 歌词响应解析、空响应和标题/歌手匹配；
- 组件无障碍摘要拼接与无歌词文本；
- 曲目定时的当前曲计数、递减和到期判断；
- 时间定时剩余值和到期判断；
- 现有歌词解析、在线匹配和播放完成回归测试。

## 不在本次范围

- 新增 TTS 引擎或第三方语音服务；
- 改变 QQ 音频播放源或跨平台音频回退；
- 将睡眠定时迁移为跨进程持久化闹钟；
- 删除桌面组件的上一首/下一首控制；
- 与本需求无关的全局 UI 重构、播放链路重构或依赖升级。
