# 在线专辑统一分页设计

## 目标

避免喜马拉雅及其他在线站点的大型专辑在一次详情请求中展开全部节目，导致上游请求过多、超时和界面长时间无内容。所有在线专辑统一按页加载，首屏快速显示，用户继续滚动时再自动请求下一页。

## 范围

- 覆盖所有经 `/v1/album/tracks` 返回曲目的站点：ShyMusic 的喜马拉雅和音乐站点、妖狐喜马拉雅后备、Sky808 有声站点。
- Android 专辑详情页首次加载保存服务端返回的续页令牌，并在用户滚动接近列表末尾时自动加载下一页。
- “下载整张专辑”在后台按页请求：每得到一页便创建该页下载任务，再继续下一页，直到没有续页令牌。
- 不改变 Android 与服务端已有的 `/v1/album/tracks` JSON 字段：继续使用 `page_id`、`sequence_offset` 和 `next_page_id`。

## 非目标

- 不引入 Jetpack Paging、数据库缓存、额外 API 端点或第三方依赖。
- 不改变单曲播放、单曲下载、搜索结果分页或播放地址解析。
- 不在滚动、焦点移动、TalkBack 浏览或页面进入时预取后续页；后续页仅由用户实际滚动接近末尾触发。
- 不为了分页修改第三方站点协议以外的 Provider 回退优先级。

## 服务端

服务端将专辑曲目页大小固定为 30。`page_id` 为空时表示第一页；续页令牌为下一页的字符串页码。`sequence_offset` 继续由 Android 传入，用于使 Sky808 等按相对页序号返回的曲目保持整张专辑连续编号。

所有 Provider 的曲目接口统一返回“本页曲目 + 下一页令牌”：

- ShyMusic 喜马拉雅：每次只请求一个上游页，传递当前页码和 `limit=30`；不再循环最多 100 页。上游页返回满 30 个有效项时返回下一页令牌。
- ShyMusic QQ、酷狗、酷我、网易云：使用页码和 30 条限制请求可分页的上游接口。若某个上游实际忽略分页参数而返回超过一页的数据，服务端仅截取当前页并返回下页令牌，保证 Android 每次只收到 30 项。
- 妖狐喜马拉雅：把 `page_id` 传为其 `pageId`，每页请求 30 条；根据本页数量和专辑已知节目数判断是否存在下一页。
- Sky808：保持现有上游游标，只把其结果纳入同一页大小和续页令牌契约。

所有 Provider 在合并或转换曲目时仍按稳定节目 ID 去重；空页或不再产生有效节目时终止分页，避免客户端无限请求。

## Android 详情页

首次请求 `RemoteOnlineCatalog.albumTracks(album)` 后，`NativeMusicViewModel` 必须同时保存本页曲目和 `nextPageToken`。详情页已有的 `LazyVerticalGrid` 滚动监听在最后可见项接近末尾 5 项、存在续页令牌且未加载/未失败时调用 `loadMoreOnlineAlbumTracks()`。

续页响应与已加载曲目按稳定 `OnlineTrack.key` 去重合并。加载期间显示现有“正在加载更多”状态；失败时保留已加载内容和续页令牌，显示现有“重试”操作。状态变化继续使用可感知的 live region，不新增仅靠颜色表达的反馈。

## 下载整张专辑

专辑下载不会再先加载完整曲目列表。流程如下：

1. 请求第一页。
2. 下载专辑封面一次，并用第一页可用曲目作为封面回退来源。
3. 按该页在专辑内的连续序号创建下载任务。
4. 存在 `next_page_id` 时请求下一页，重复第 3 步。
5. 直到没有续页令牌后，汇总成功、跳过和失败数量并公告结果。

任何分页请求失败时停止后续页，但已创建的下载任务保留；状态文本明确表示已处理数量及失败原因。下载任务创建继续复用现有队列与并发控制，不会在 ViewModel 中并行展开多个曲目页。

## 错误与边界

- 首批请求失败：详情页显示现有加载失败状态和重试操作。
- 后续请求失败：详情页保留当前列表及令牌，用户可点击重试；整专辑下载停止后续请求并显示部分结果。
- 空页、重复页或未返回有效曲目：清除续页令牌，避免自动分页死循环。
- 用户离开专辑详情页时，过期页请求的回调不得写入其他专辑状态。
- 自动分页仅由滚动位置触发，不由无障碍焦点、列表选择或普通重组触发。

## 测试与验收

- 服务端测试：ShyMusic、妖狐和 Sky808 的首/续页请求参数、每页最多 30 项、正确的下一页令牌、空页终止及全局序号。
- Android 单测：`RemoteOnlineCatalog` 保留服务端页令牌；`NativeMusicViewModel` 首批保存令牌、续页合并去重、失败保留可重试状态；专辑下载按页请求并逐页创建任务。
- UI 验收：大型喜马拉雅、蜻蜓 FM、酷我听书或酷狗听书专辑首批快速出现，手势滚动到末尾后自动加载一页，TalkBack 浏览不发起请求，加载与失败状态可感知。
- 质量门槛：`rtk git diff --check`、服务端测试、Android 相关单测和 `rtk cmd /c "gradlew.bat :app:assembleRelease"` 必须通过；涉及 UI 的手工检查遵守 48dp 目标、中文语义、对比度和焦点规则。
