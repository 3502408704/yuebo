# 网易云流媒体控制设计

## 目标

在线网易云曲目继续支持进度拖动、长按快进快退、倍速和 A-B 循环，同时避免网络缓冲或地址获取失败被误判为歌曲结束并自动跳到队列下一首。

## 根因

`BASS_StreamCreateURL` 创建的解码网络流在缓冲期间可以暂时没有 PCM 数据，但其通道仍是活动状态。现有输出循环把 `BASS_ChannelGetData` 返回零直接当作自然结束，触发完成回调和自动换歌。此前移除 Tempo 流和禁用控制只是绕过现象，破坏了所需功能。

## 设计

`NativeBassPlayer.playUrl` 保持非 `BASS_STREAM_BLOCK` 的 URL 解码流，并重新以 `BASS_FX_TempoCreate` 包装它。BASS 因此持续下载整首文件，已经缓冲到的位置可被定位，Tempo 流继续提供 0.5 到 2.0 倍速。

播放器对同一流的解码、定位、设置倍速和释放操作使用同一个短时同步边界，避免 UI 控制与输出线程同时操作 BASS 通道。输出循环仅在网络流的解码通道真正停止时触发完成；零数据但仍活动时等待下一次解码，不换歌。

定位请求若目标数据尚未缓冲，播放器不结束当前播放。ViewModel 在有限时间内等待并重试同一个定位请求，成功后更新进度；超时后保留原位置并给出可见错误状态。快进、快退、进度条和 A-B 循环均调用同一定位路径。倍速直接设置 Tempo 属性，不重新请求播放地址。

## 地址与失败策略

地址仍只在进程内按曲目和音质缓存。缓存地址失效时驱逐并按 VIP 两次、免费两次重新解析。四次都失败后，将该曲目标记为本次显式播放失败，停止在当前曲目，不自动推进队列，也不在后台继续请求。用户重新点播、上一首或下一首才开始新的请求周期。

获取地址和缓冲过程不触发 TalkBack 播报；只有成功进入新的当前音频时播报正在播放。定位失败保留可见中文状态，现有进度、速度和长按操作保持可访问语义与 48dp 目标。

## 验收

- 网络缓冲期间不自动换歌。
- 网易云曲目能拖动进度、长按快进快退、设置倍速和设置 A-B 循环。
- 缓冲不足的定位会等待或失败回到原位置，不造成卡死或换歌。
- 地址失败最多解析四次，不自动请求队列下一首。
- 缓存地址优先使用，失效后才重新解析。
